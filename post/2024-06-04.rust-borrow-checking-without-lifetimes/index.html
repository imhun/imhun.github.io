不带生命周期的借用检查

来源：Borrow checking without lifetimes，Niko Matsakis，2024-03-04

一句话概括：把 'a 从“生命周期”重新解释成“一组借出（loan）”。

生命周期是 Rust 最难教的东西之一——它代表“代码的某段区间”这种用户平时不会去想的概念，而且没有任何语法形式。换成借出集合之后，'a 的含义变成“这个引用可能是从哪些地方来的”，可以直接写出来：

1
2
3

Origin = { Loan }
Loan   = shared(Place) | mut(Place)
Place  = variable(.field)*     // 例如 a.b.c

于是类型写成 & {shared(counter)} u32 这样。今天的 Rust 没有语法能表达这个——这正是问题所在。

这不是新东西，它就是 Polonius 的基础，区别只在于这里是把它表述成类型系统，而不是静态分析。

类型判断要带上 liveness

只有类型不够，还要知道“将来会访问哪些 place”。所以判断的形式变成：

1

(Env, LivePlaces) |- Expr : Type

意思是：在环境 Env 下，已知函数将来会访问 LivePlaces，表达式 Expr 合法且类型是 Type。

引入借出的规则很直接——&Place 的 origin 就是“从 Place 借”：

1
2
3

Env |- Place : Type
------------------------------------- 共享引用
Env |- & Place : & {shared(Place)} Type

借用检查：permits

核心是一条“允许”规则：活跃集合里的每个 place，其类型中出现的借出都要和当前要取的借出兼容。

1
2
3
4
5
6

∀ Place ∈ Live {
    (Env, Live) |- Place : Type
    ∀ Loan2 ∈ Loans(Type) { Compatible(Loan1, Loan2) }
}
-------------------------------------
(Env, Live) permits Loan1

Compatible 的规则是：两个共享借出永远兼容；可变借出只在两个 place 不相交时才兼容。

拿例子走一遍：

1
2
3
4

let mut counter: u32 = 22_u32;
let p: &{shared(counter)} u32 = &counter;  // 需要一种今天没有的语法
counter += 1; // 错误
println!("{p}"); // p 是 live

因为下一行要用 p，p 在 LiveAfter 里；p 的类型含 shared(counter)，所以对 counter 取 mut(counter) 不兼容，报错。

一个反直觉的地方

liveness 是倒着算的，而类型规则是正着往前流的。所以 Expr1 + Expr2 的规则要先算 LiveAfter1 = LiveBefore(Env, LiveAfter2, Expr2)——把后面活跃的集合倒推回来，再拿去检查 Expr1。

理解它的办法是把 + 完整脱糖：

1
2
3

let tmp0 = <Expr1>   // 这里活跃的是 LiveAfter1
let tmp1 = <Expr2>   // 这里活跃的是 LiveAfter2
tmp0 + tmp1

另一个让规则变简单的关键：把 liveness 放进判断里。作者说这一点他一开始也没看出来，试过别的写法都不行。

为什么这条路值得走

有了显式的 place 语法，两件事会变容易：

  1. 好教。 不用再解释“某个生命周期对应代码的哪一段”，直接说“这是一个引用变量 list 的 String”
  2. 能表达现在表达不了的东西。 命名 place 打开了更灵活的借用，比如一个 struct 的字段引用另一个字段的数据——见 dada 的内部引用 里的 Vec[ref[self.list] String]
