从这篇开始，Dada 真的像 Rust 了。

类

最省事的写法是把字段放进括号，同时隐式声明一个构造函数：

1

class Point(x: u32, y: u32) {}

它是下面这个更像 Rust 的写法的语法糖：

1
2
3
4
5
6
7

class Point {
    x: u32
    y: u32
    fn new() -> Point {
        Point { x, y }
    }
}

默认只读，! 才可变

参数默认拿到的是只读访问，试图改字段会报错：

1
2
3

fn print_point(p: Point) {
    p.x += 1 # 错误
}

加上 ! 就变成指向调用方实例的可变引用，等价于 Rust 的 &mut Point：

1
2
3
4
5
6
7

fn translate_point(point!: Point, x: u32, y: u32) {
    point.x += x
    point.y += y
}

let p = Point(22, 44)
translate_point(p!, 2, 2) # 调用点也要带 !

移动是显式的

这是和 Rust 差得最明显的一处。Rust 里 print_point(p) 会移动 p，之后就不能再用了；Dada 默认给的是只读引用。

需要所有权时参数声明写 given，调用方用 .give：

1
2
3
4
5

fn take_point(p: given Point) { ... }

let p = Point(22, 44)
take_point(p.give)
take_point(p.give) # 错误：不能给两次

和 Rust 对照

RustDada
vec.len()vec.len()
map.get(&key)map.get(key)
vec.push(element)vec!.push(element.give)
vec.append(&mut other)vec!.append(other!)
message.send_to(&channel)message.give.send_to(channel)

为什么这么设计

方便是默认的。 最常用的写法应该最短，所以读成了默认。

一切显式，但不啰嗦。 Rust 的 . 具体做什么取决于调用的方法——可能改、可能移动、可能建临时值；Dada 要求在调用点就能看出来。这条规矩其实来自早期做渐进编程的日子：方法上没有类型标注时，没法判断 foo.bar() 该拿共享借用还是可变借用，所以需要一种在调用点就能看清一切、又显式的记法。

后缀运算符更好组合。 Dada 尽量不用 &mut 这种前缀运算符，它们和 . 记法配合得不好。

一处别被误导的类比

说“Dada 默认给只读引用，相当于 &x”只有直觉上的对。实际有误导——Dada 的引用和 Rust 有一处非常关键的不同，见 dada 的内部引用。
