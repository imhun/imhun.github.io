Dada：不用调 as_ref() 的 Rust

来源：Fun With Dada，Niko Matsakis，2026-02-08 系列：Dada

Dada 是作者从 2021 年就开始做的实验语言，搞了好几年一篇博客都没写过。它完全不能用于生产——编译器跑不起来，因为他老是在语言做通之前就把它改了。用他的话说，更像是个“减压阀”：设计一门不用管向后兼容、不用管 RFC 的语言，本身就是乐趣。

但它是个不错的想法来源，而且不止对语言设计有用：为了按自己想要的方式写 Dada 编译器，他重新设计了 salsa，现在 rust-analyzer 和 Astral 的 ty 都在用。

走过的弯路：渐进类型

早期目标是做一门渐进类型的语言，理由是更好学：可以完全不写类型直接跑程序，还有个交互式 playground 能一步步展示权限（permissions，就是 Dada 版的借用检查器）的状态。这部分当时确实做出来了，2022 年在 PLMW 上还讲过一次。

后来他不信这条路了。他想要的效果是“不写类型跑程序时，在违反借用规则的那一点报错”——这意味着程序得跟踪大量额外数据（有点像 miri 的做法），实际上只适合当教学工具。为了一个只在学习最初期有用的东西给语言增加这么多复杂度，不划算。 于是推倒重来，只做静态类型检查。

现在的定位：精简版 Rust

目标是 Rust 那种“以所有权为核心”的手感，但要做的选择和要抠的细节少得多。

Rust 里有一堆语义等价、表示不同的类型。&Option<String> 和 Option<&String> 能做的事完全一样，可必须仔细区分；&Vec<String>、&Vec<&String>、&[String]、&[&str] 及其变体也是一样的情况。

在 Dada 里它们都是同一个类型。 而且不是靠把所有东西堆分配或者上 GC 实现的。

一句话概括：“永远不用调 as_ref() 的那种 Rust”。

借用检查器走在 Rust 前面

Dada 已经实现了《借用检查器内部》里设想的很多东西，只差 view types：

能力说明
内部借用结构体的字段可以借用同一结构体的其他字段
无生命周期标注的借用检查用 place 代替生命周期

这些大多可以搬回 Rust，Dada 里他改了几处，让某些方面更容易实现。

为什么只做 WebAssembly

选 WASM 组件最初是为了方便：

  • 它像一门简单干净的汇编，写后端很容易
  • 组件模型本来就是为跨语言设计的，FFI 问题它替你解决
  • 配上 WASI 连标准库都有，包括“抓取网页”这种高级功能，所以能立刻做出有用的东西

后来他意识到一个更大的好处：编译期反射几乎零成本。

Dada 编译器是纯按需编译的，可以把一个函数一路编成 WASM 字节码、其他部分原封不动。有了字节码，就能在编译器内部运行它——wasmtime 是高质量的 JIT，跑得快，而且代码还是沙箱化的。

于是就能这么干：编译一个函数 → 在编译过程中运行它 → 用它生成别的代码，供编译的其它环节使用。相当于白送一个 miri 或者 Zig 的 comptime。

现状

还不能用。作者打算继续推编译器，尽快做到能跑 live demo，具体多久不好说。在那之前，他会写一系列博客讲类型系统、借用检查器和编译器架构，顺带帮自己重新捡起这些细节。
